# MeetMind — PDF Meeting Notes + Standalone Watch Recording

**Date:** 2026-06-13
**Status:** Approved
**Motivation:** Genspark-style PDF export of meeting notes; an Apple Watch you
can tap to record an in-person meeting.

## Context

MeetMind is already a near-complete iOS meeting app. The working loop:
record (AAC/m4a, background-safe, auto-chunking) → transcribe (Groq Whisper,
cloud) → AI notes (Groq Llama / Gemini: markdown summary + structured
`MeetingBrief`) → persist (programmatic Core Data) → todos, chat, templates,
note enhancement, follow-up emails, JSON/CSV export.

This work adds two missing capabilities. Neither requires new AI keys; both
reuse the existing pipeline.

## Decisions made with the user

1. **PDF content** — full branded notes doc: header band, summary, decisions,
   action items (checkboxes), key topics, key quotes, open questions, plus a
   full speaker-labeled transcript appendix (toggle, **default on**).
2. **Watch recording** — watch records audio standalone (AVAudioRecorder) and
   transfers the file to the phone via WatchConnectivity; the phone transcribes
   + generates notes. Works when the phone is out of mic range.
3. **Watch surface** — full watch app (record button + live timer + stop) PLUS
   a watch-face complication that one-taps into recording.
4. **Run target** — build to the user's iPhone + Apple Watch via Xcode with
   their Apple ID (free personal provisioning).
5. **Orphan cleanup** — after promoting the real recorder, delete the two
   unreferenced orphan folders `MeetMindWatch/` and `MeetMindwatchos/`.

## Build hygiene (critical)

`project.yml` is stale: it declares only the iOS `MeetMind` target, NOT the
watch app / widget / watch-widget targets that exist in `MeetMind.xcodeproj`.
Running `xcodegen generate` would WIPE those targets. Therefore:

- Do NOT run `xcodegen`. Build `MeetMind.xcodeproj` directly with `xcodebuild`.
- Add a warning header to `project.yml` documenting that the `.xcodeproj` is the
  source of truth.

The wired watch app target's folder (`MeetMindWatch Watch App/`) and the watch
widgets folder (`MeetMindWatchWidgets/`) are `PBXFileSystemSynchronizedRootGroup`s
— files dropped into them are auto-included in the target, so promoting the
recorder needs no pbxproj editing.

## Part A — PDF meeting notes

### MeetingPDFRenderer (new, MeetMind/Services)

Pure rendering: `render(meeting:includeTranscript:) -> Data` using
`UIGraphicsPDFRenderer` at A4 (595×842 pt) with ~48 pt margins.

A small `PDFLayoutContext` value type owns the cursor and pagination:
- `cursorY`, current page, page size, margins
- `ensureSpace(_ height:)` — starts a new page (drawing footer on the old one)
  when the next block won't fit
- `drawFooter()` — "Generated by MeetMind · {date} · page N"
- helpers: `drawSectionTitle`, `drawParagraph(attributed:)`, `drawBullet`,
  `drawCheckbox(checked:text:meta:)`, `drawChips`, `drawBlockquote`, `drawRule`

Document structure:
1. **Header band** — accent-filled rounded rect: "MeetMind" wordmark, meeting
   title, `date · duration · clientName`, template badge.
2. **Summary** — `briefSummary` is markdown; render via a small
   markdown→`NSAttributedString` converter supporting `#/##/###` headers,
   `**bold**`, `*italic*`, and `- ` / `* ` bullets. (If `AttributedString(markdown:)`
   covers it acceptably, prefer the stdlib path; otherwise the subset converter.)
3. **Decisions** — numbered list (skip section if empty).
4. **Action items** — checkbox glyph (☐/☑ by `isCompleted`) + text + `owner`
   + due date; "(you)" marker when `isMine`.
5. **Key topics** — wrapped chips.
6. **Key quotes** — blockquote with left accent rule.
7. **(Open questions omitted in v1)** — the `Meeting` struct persists only
   `briefDecisions/briefActionItems/briefKeyTopics/briefKeyQuotes`; open
   questions live only on the transient `MeetingBrief` and are not stored, so
   there is nothing to render. Do not invent the data.
8. **Transcript appendix** — page break, "Transcript" title, speaker-labeled
   paragraphs from `rawTranscript`, only when `includeTranscript`.

Empty sections are skipped entirely (no empty headers).

### Integration

- Extend `DataExportService` with
  `exportMeetingAsPDF(_ meeting: Meeting, includeTranscript: Bool) -> URL?`
  writing `meetmind_{safeTitle}.pdf` into the existing temp-export dir.
- `MeetingDetailView` toolbar (~line 240): add an **Export** menu with
  "Export as PDF" → existing `ShareSheet` (`showShareSheet` / `shareItems`).
- Settings: `includeTranscriptInPDF` toggle (UserDefaults, default `true`).

### Error handling

Render failure → return nil → detail view shows an alert ("Couldn't create
PDF"). No partial files surface to the share sheet.

## Part B — Standalone watch recording + complication

### 1. Promote the recorder

Replace the stub `MeetMindWatch Watch App/MeetMindWatchApp.swift` (record button
is an empty closure) with the real `WatchRecorder` currently orphaned in
`MeetMindWatch/MeetMindWatchApp.swift`: AVAudioRecorder (16 kHz mono AAC, 32 kbps),
1 s duration timer, `WKInterfaceDevice` haptics on start/stop/sent,
`WCSession.transferFile(_, metadata:)` with `{type:"audioRecording", fileName,
timestamp, duration}`. Delete the unused `ContentView.swift` root note.

On-appear: if the shared App-Group flag `pendingStartRecording` is set (from the
complication intent), clear it and auto-start recording.

Delete orphan folders `MeetMindWatch/` and `MeetMindwatchos/`.

### 2. Close the iOS gap (the linchpin)

Today `WatchConnectivityService.session(_:didReceive:)` saves the file and posts
`audioFileReceivedNotification`, but nothing observes it. Add an observer in
`MeetingService` (registered once at app launch alongside the existing
`WatchConnectivityService.shared.activate()` in `MeetMindApp`):

```
on audioFileReceivedNotification(fileURL, metadata):
  create Meeting(title: "Watch recording", date: now,
                 duration: metadata.duration ?? 0,
                 audioFilePath: fileURL.lastPathComponent,
                 status: .processing)
  persist; then MeetingPipeline.process(meeting) → notes
  post a UI banner "Watch recording received — processing"
```

Reuse the exact pipeline a phone recording uses; do not fork transcription/notes
logic. On pipeline failure the existing `.failed` + reason path applies.

### 3. Face complication ("widget")

In `MeetMindWatchWidgets`: an `accessoryCircular` (and `accessoryCorner`)
complication showing a mic glyph. Tapping fires a `StartRecordingIntent`
(`AppIntent`, `openAppWhenRun = true`) that sets the App-Group
`pendingStartRecording` flag and opens the watch app, which auto-starts
recording on appear. watchOS widgets cannot capture audio, so launching the app
is required and intentional.

App Group: reuse/confirm the existing group id used by `WidgetDataShared` /
`MeetMindWidgetData`; add `pendingStartRecording: Bool` to the shared defaults.

### Data flow (in-person meeting)

tap complication → watch app opens & records → stop → file transfers (queues if
phone away) → iOS observer creates Meeting + runs pipeline → notes ready →
user exports PDF.

## Testing

- `MeetingPDFRendererTests` — render a fixture `Meeting` (summary + 2 action
  items + transcript). Assert: non-empty `Data`, `PDFDocument(data:).pageCount >= 1`,
  and extracted text contains the title and an action item's text. Run with
  `includeTranscript` true and false (page count differs).
- `WatchAudioIngestTests` — pure mapping `(fileName, metadata) -> Meeting`
  fields (title/duration/audioFilePath/status), no I/O.
- Manual on-device: real mic recording on watch, transfer to phone, auto-notes,
  PDF export + share. (Simulator can't validate watch audio.)

## Signing / run

Set `DEVELOPMENT_TEAM` to the user's personal team (or leave Automatic and have
them pick their Apple ID team in Xcode → Signing). Bundle ids stay consistent:
`com.meetmind.app`, `.watchkitapp`, widget/watch-widget extensions. Document the
exact Xcode steps in the README/run notes.

## Out of scope (v1)

- Watch-as-remote-control of phone recording (we chose standalone).
- Multi-meeting batch PDF export.
- Live transcript streaming to the watch.
- Notarization/TestFlight (free personal device install only).
- Re-homing the Mac app or touching xcodegen.
